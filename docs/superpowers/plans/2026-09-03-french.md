# French Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every user-visible string in MyQuizzlet available in French, switchable by a flag button in the topbar that shows the language currently in use.

**Architecture:** A tiny `t(key, params)` over two flat dictionary modules, `app/i18n.en.js` and `app/i18n.fr.js`. The chosen language lives in the same local settings blob as the theme (per-device, never synced). Screens are converted one at a time; each conversion is a separate commit, and the app is fully working in both languages after every one. The long Help prose is the deliberate exception: it lives in two prose modules rather than in the dictionary.

**Tech Stack:** Hand-written ES modules, no build step, no dependencies. Vitest for the pure parts.

**Spec:** `docs/superpowers/specs/2026-09-03-french-and-effects-design.md`

## Global Constraints

Copied from the spec and from `CLAUDE.md`. Every task's requirements implicitly include these.

- **No build step, no bundler, no framework, no CDN script tag.** ES modules loaded directly by the browser.
- **Every new module under `app/` must be added to `SHELL` in `sw.js` in the same commit, and `const CACHE = 'myquizzlet-vN'` bumped.** `test/sw.test.js` scans `app/` and `app/screens/` and fails if a module is missing from `SHELL`, so a forgotten entry breaks the suite immediately.
- **New modules go flat in `app/`, not in a new subdirectory.** `test/sw.test.js` only scans `app/` and `app/screens/`; a file in `app/lang/` would silently escape the check. Hence `app/i18n.en.js`, not `app/lang/en.js`.
- **Never write a token into a file in this repo.**
- **A missing translation key falls back to the English string, never to the raw key.**
- **User data is never translated:** card fronts and backs, list names, folder names, and side labels are the user's words.
- **The chosen language is per-device**, stored in `mq:settings` alongside `theme`. Nothing is added to the synced data.
- Run the suite with `npm test`. Serve the app with `python3 -m http.server 8000` and open `http://localhost:8000`.

## Key naming convention

Flat, dot-separated, `<screen>.<thing>`: `lists.title`, `lists.empty`, `train.setup.blurb`, `nav.settings`. Shared strings that genuinely appear on several screens use the `common.` prefix: `common.back.lists`, `common.cards`, `common.due`, `common.unfiled`.

Count-dependent strings are stored as a `_one`/`_other` pair — `common.cards_one` / `common.cards_other` — and requested with `{ n }`.

**Created:**

|---|---|
| `app/i18n.js` | `t`, `lang`, `setLang`, and the pure `plural` / `translate` helpers |

- [ ] **Step 4: Write `app/i18n.js`**

```js
import { settings, saveSettings, ctx } from './app.js';
import { en } from './i18n.en.js';
import { fr } from './i18n.fr.js';

export const DICTS = { en, fr };

// French puts zero in the singular, English does not. That is the entire rule.
export function plural(langCode, n) {
  if (langCode === 'fr') return n < 2 ? 'one' : 'other';
  return n === 1 ? 'one' : 'other';
}

// Pure, so it can be tested without a browser or a settings blob.
// A missing key falls back to the English string; only a key that exists in
// neither dictionary comes back as itself.
export function translate(dict, fallbackDict, langCode, key, params = {}) {
  const wanted = params.n === undefined ? key : `${key}_${plural(langCode, params.n)}`;
  const text = dict[wanted] ?? fallbackDict[wanted] ?? key;
  return text.replace(/\{(\w+)\}/g, (whole, name) =>
    (params[name] === undefined ? whole : String(params[name])));
}

export function lang() {
  return settings().lang === 'fr' ? 'fr' : 'en';
}

export function t(key, params) {
  const code = lang();
  const text = translate(DICTS[code], en, code, key, params);
  if (text === key) console.warn(`i18n: no string for ${key}`);
  return text;
}

// The language is per-device, like the theme: it lives in the same local
// settings blob and is never synced.
export function setLang(code) {
  saveSettings({ ...settings(), lang: code });
  document.documentElement.lang = code;
  ctx.render();
}
```

**Why this is not in the dictionary:** long-form prose is written and edited as prose. Sixty paragraph-sized keys would make both languages worse to edit and would force the French to track the English sentence for sentence instead of saying the same thing the way French says it.

- [ ] **Step 5: Pick the prose by language**

In `app/screens/help.js`:

```js

import { helpFr } from './help.fr.js';

```

and read every string from `prose()` inside the render function, never from a module-level constant — a constant would freeze the language at load.

- [ ] **Step 6: Add a shape test**

Append to `test/i18n.test.js`:

```js
import { helpEn } from '../app/screens/help.en.js';
import { helpFr } from '../app/screens/help.fr.js';

describe('the help prose', () => {
  it('has the same sections in the same order in both languages', () => {
    expect(helpFr.sections.length).toBe(helpEn.sections.length);
    helpEn.sections.forEach((section, i) => {
      expect(helpFr.sections[i].paragraphs.length).toBe(section.paragraphs.length);
    });
  });

  it('leaves nothing empty', () => {
    const blank = [helpEn, helpFr].flatMap((prose) => prose.sections)
      .flatMap((section) => [section.heading, ...section.paragraphs])
      .filter((text) => !text || !text.trim());
    expect(blank).toEqual([]);
  });
});
```
